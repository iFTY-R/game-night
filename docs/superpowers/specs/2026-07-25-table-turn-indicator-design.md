# 桌面行动玩家与顺序指示设计

## 1. 范围

本次变更解决两个直接相关的问题：当前行动玩家只能依赖桌面中央或操作区文案识别，以及顺序制游戏没有贴合桌沿的方向反馈。

变更只涉及共享游戏桌、顺序制游戏的展示适配及相应测试，不改变游戏引擎、座位推进规则、实时投影协议、操作权限和回放数据。

本文覆盖并替代《玩家用户名与桌沿席签设计》第 3 节中“当前行动玩家显示外部行动标记”的视觉要求；其它席签要求继续有效。

## 2. 行动玩家

- 当前行动玩家的座位卡持续使用高对比边框、外圈光晕和轻量呼吸效果，不改变卡片尺寸或座位位置。
- 不再显示“轮到你”“行动中”或“轮到某人”等可见浮签。玩家名与游戏提供的业务状态继续留在座位卡内。
- 桌面中央和操作区可以继续展示游戏本身的回合文案与倒计时，但它们不再是识别当前行动玩家的唯一来源。
- `TableSeat` 新增独立的 `turn` 状态，只表示该玩家当前被期望执行顺序制操作。现有 `active` 保留为通用强调态，可继续表示已提交、胜者或复盘焦点，不能产生回合语义。
- 当前行动座位使用独立的 `is-turn` 视觉状态；通用 `active` 可以保留较弱强调，但不得复用行动玩家的持续呼吸效果。
- `turn` 由游戏投影适配层按当前阶段和权威行动者决定。终局、结算中没有单一行动者、同时操作或投影没有有效行动者时，所有座位的 `turn` 必须为空。
- 可访问名称仅在 `seat.turn` 为真时包含“轮到你”或“行动中”语义，使移除可见浮签不会丢失屏幕阅读器信息，也不会把已提交、胜者或复盘焦点误读为当前回合。

## 3. 桌边顺序

共享 `GameTable` 增加可选、显式的桌面方向输入，取值仅为 `clockwise` 或 `counterclockwise`。组件不得根据座位编号或数组顺序猜测业务方向。

方向存在且桌上至少有两名玩家时，桌沿显示一个非交互箭头：

- 箭头中心沿现有可见桌沿低速、匀速巡行，只表达整体行动方向，不得使用向桌内缩进的独立椭圆轨迹。
- 默认标记尺寸为 16px、图标尺寸为 10px，一圈默认 12 秒；经过桌沿座位时从卡片后方穿过，不得覆盖玩家名或状态。
- 不显示“顺时针”“逆时针”等可见文字，也不增加说明标签或可点击控件。
- 方向反转时，运动方向和箭头朝向同时反转，不重建座位或改变当前玩家高亮。
- 箭头颜色优先使用游戏主题的 `--game-direction`，缺失时回退到平台强调色；光晕、透明度和运动时长通过共享 CSS 变量提供可覆盖默认值，主题可覆盖默认 12 秒周期。
- 桌边巡行箭头成为实时桌唯一的可见方向图标；游戏中央不再重复显示顺时针或逆时针图标。

各游戏按真实玩法决定是否启用：

- `dice-789`：把投影中的实际方向映射为顺时针或逆时针；按阶段显式解析权威行动者。普通摇骰、加注、选择目标和继续阶段由 `currentUserId` 对应座位进入 `turn`；等待房主确认时由桌面上下文中的房主座位进入 `turn`；结束状态不设置 `turn`，也不显示巡行箭头。实时桌中央现有方向图标移除。
- `liars-dice`：进行中的轮流叫骰固定传入顺时针，并让 `currentActorUserId` 对应座位进入 `turn`；结束状态不设置 `turn`，也不显示巡行箭头。
- `three-rounds`：玩家同时选牌，不存在单一行动顺序，不设置 `turn`，也不显示巡行箭头。现有 `active` 所表达的已提交或胜者状态继续只作为通用席位强调，不产生行动播报。
- `meet-by-chance`：靶子可能连续重摇，且使用独立桌面和靶子语义，不用固定顺时针箭头替代真实玩法；继续由靶子席位高亮表达当前决策者。
- 房间等待桌面和所有复盘桌面不设置 `turn`，也不显示巡行箭头。789 复盘中的历史方向图标属于单回合结果内容，可以继续保留。

## 4. 响应式与动效

- 箭头轨迹必须复用 `GameTable` 可见桌沿的响应式 inset 与圆角几何，箭头中心在竖屏和横屏下始终贴合桌沿；经过座位时由座位卡自然遮挡，箭头本身不得覆盖玩家名、中央游戏内容、私密区或操作托盘。
- 操作托盘展开、折叠只影响现有安全区和中心位移，不改变箭头速度或造成轨迹跳动。
- 当前玩家的 `is-turn` 光晕不改变席位布局尺寸，不扩大交互命中区，也不新增点击行为。终局或阶段切换清空 `turn` 后，呼吸效果立即停止。
- `prefers-reduced-motion: reduce` 下停止巡行动画和呼吸动画，保留静态方向箭头、稳定边框及光晕。
- `[data-motion="reduced"]` 继续通过共享主题规则把动画收敛为单次瞬时状态。
- 动画使用 CSS 合成属性，避免逐帧 JavaScript 定时器和响应式状态更新。

## 5. 可访问性

- 桌边箭头是 `aria-hidden` 的装饰层，不是按钮，也不进入键盘焦点顺序。
- `GameTable` 根节点内只渲染一个 sr-only 方向描述，屏幕阅读器可读为“游戏顺序：顺时针”或“游戏顺序：逆时针”，避免动画元素重复播报。
- 当前行动玩家只通过 `seat.turn` 驱动的座位卡 `aria-label` 声明行动状态；通用 `active` 不产生行动语义。颜色和动画不是唯一的无障碍信息来源。
- 高对比主题下使用平台高对比强调色回退，箭头和当前席位边框必须保持可辨识。

## 6. 验收标准

1. `seat.turn` 对应的当前行动玩家只显示持续边框与光晕，不再渲染任何可见行动浮签；普通玩家、自己、房主和离线状态保持原有卡片结构。仅 `active` 而没有 `turn` 的已提交、胜者和复盘焦点不会播报“行动中”。
2. 吹牛骰子进行中显示顺时针桌边箭头，当前行动玩家切换后只有对应座位进入 `is-turn`；结束状态清空 `turn` 并隐藏箭头。
3. 789 的顺时针和逆时针投影分别产生对应巡行方向与箭头朝向，方向反转不改变座位布局；等待房主确认时高亮房主，结束状态清空 `turn` 并隐藏箭头；实时桌中央不再显示第二套方向图标。
4. 三关定胜负、喜相逢、房间等待桌面及所有复盘桌面不显示虚假的顺序箭头，也不设置 `turn`；自动化测试显式覆盖这些无箭头状态。789 复盘可保留历史结果中的静态方向图标。
5. 在 `360x740`、`390x844` 和 `844x390` 下，箭头中心轨迹与可见桌沿重合，经过座位时从卡片后方穿过，不遮挡座位、中央内容、私密区或操作托盘；操作托盘状态切换和横竖屏切换不造成布局跳动。
6. `prefers-reduced-motion: reduce` 下箭头和席位光晕没有持续动画，但方向、当前席位边框和可访问名称仍然存在。
7. 组件测试覆盖无方向、顺时针、逆时针、远端当前玩家、本地当前玩家、仅通用 `active` 和终局清空；游戏客户端测试覆盖方向映射、789 房主确认阶段、结束状态隐藏，以及等待桌与复盘桌不继承箭头。
8. Web 类型检查、相关单元测试、生产构建和桌面 Playwright 用例全部通过，视觉检查确认竖屏与横屏均无重叠。
