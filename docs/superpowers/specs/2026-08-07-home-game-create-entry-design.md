# 首页按游戏创建房间设计

## 目标

让用户先从游戏列表确定要玩的游戏，再选择房间的加入方式。创建入口与游戏项直接关联，避免“先选中游戏、再到页面其他位置创建”的割裂操作。

## 交互

- 每个游戏项展示游戏名称、简介、最低人数和独立的“创建房间”按钮。
- 点击按钮时记录对应游戏，并打开房间类型弹窗。
- 用户在弹窗中点击“仅邀请”或“公开房间”后立即创建对应游戏的房间。
- 游戏项本身不再可点击，也不保留选中态。
- 加入区域只负责通过房间码加入，标题改为“加入房间”，并删除页面级创建按钮。

## 响应式布局

- 桌面端游戏项保持图标、游戏信息、人数提示和创建按钮同一行，便于快速扫描。
- 移动端压缩次要信息宽度，但创建按钮仍与游戏信息同行，避免每个游戏项变成过高的两层操作卡片。
- 按钮和弹窗均保留明确的键盘焦点、可访问名称和忙碌状态。

## 状态与错误

- 打开弹窗前清除上一次创建错误。
- 创建期间禁用弹窗选项，防止重复请求。
- 创建失败时错误留在弹窗内，用户可直接重试或关闭。
- 创建成功后沿用现有流程，将选择的游戏提交到房间并进入房间页。

## 验证

- 单元测试覆盖“游戏项按钮打开正确游戏弹窗”和“选择房间类型后提交创建”。
- 端到端测试覆盖非默认游戏创建、公开/仅邀请类型以及创建后的游戏参数。
- 在桌面、390px 和 320px 视口检查游戏项不溢出、按钮不换行遮挡、弹窗可完整操作。
